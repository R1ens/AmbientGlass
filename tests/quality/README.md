# Glow quality checks

Quantitative image-quality regression tests for the glow renderer. They render synthetic pictures with
the headless renderer (`VlcAmbient.exe --render`, WARP), paste the picture into the transparent hole
of each output and measure the glow next to the picture. You only need Python 3 (standard library).

```bat
python tests\quality\check_quality.py --exe build\VlcAmbient.exe
```

| Option | Meaning |
|---|---|
| `--exe PATH` | renderer to test (default `D:\VlcAmbient\build\VlcAmbient.exe`) |
| `--work DIR` | where inputs and renders go (default: a new temp dir, deleted at exit) |
| `--keep` | keep the temp work dir |
| `--self-test` | run the same measurements on ideal outputs built in Python (see below) |

The script prints one line per measurement (`PASS`/`FAIL`, value, limit, where it was worst) and a
summary. It exits with 0 if everything passes, 1 if any measurement fails, and 2 on a usage or render
error. A full run takes about 15 s (25 renders at 3840x1080).

Geometry: a 1920x1080 picture centred in a 3840x1080 output (`--frame 960,0,2880,1080 --opaque
--seed 0`, `debanding=0`), so the output is deterministic and has no dither. Luminance is Rec.709
luma of the 8-bit sRGB values (0..255 "levels"). `k` is the distance from the picture edge outward:
`k = 0` is the first glow pixel. `T` is the transition width (`edgeBlend / 100 * 0.2 * 1080` px).

## Checks

| Check | Guards | Measures |
|---|---|---|
| `transition_monotonic` | Defect 1: shelf or trough in the near-field transition | On `lum_x` and `flatgrey` with default settings, `blur=100`, `blur=100,spread=60`, `edgeBlend=100` and `spread=5,edgeBlend=100`, along row 540 on both sides: **rise after fall** (max of `L[k] - min L[<k]`, must be <= `T_RISE`); **kink** (largest second difference of 6-px window means for `k < 1.25 T`, must be <= `max(T_KINK_ABS, T_KINK_REL * 6 * drop * 36 / T^2)`, where the second term is 1.5x the curvature a smoothstep needs to make the same drop over `T`); **shelf** (the drop per 6-px window must rise to one peak and then fall; any dip below the earlier and later maxima must be <= `T_SHELF`); **seam step** (`abs(first glow px - last picture px)` <= `T_SEAM`, for `edgeBlend >= 40`) |
| `left_right_symmetry` | Defect 2: left/right asymmetry and dependence on output width | `symx` (a mirror-symmetric picture) with default settings, `edgeBlend=0`, `edgeBlend=0,blur=0` and `edge=2`: max per-channel `abs(left glow - mirrored right glow)` over every 8th row and `k < 600` (limit `T_SYM`). The same picture at 3700 and 3840 px output width, frame re-centred: max per-channel difference at equal offsets from the seam (limit `T_WIDTH`) |
| `edge_detail_fidelity` | Defect 3: the first glow column ignores detail along the edge | `stripes16` and `stripes64` (grey bands about 16 or 64 px tall, constant along x) with default settings, `edgeBlend=100` and `blur=100`: RMS over rows 100..979 of `L(first glow column) - L(last picture column)` (limits `T_DETAIL_RMS`). `hstripes6` (3 px on, 3 px off) is reported as `INFO` only and does not fail the run |
| `negative_fade_start` | Defect 4: `fadeStart < 0` cuts a dark step into the seam | `fadeStart=-50` with the default `edgeBlend=40` on `flatgrey` and `lum_x`: seam step <= `T_NEGFADE_SEAM` |
| `edge_rays` | Defect 5: a sharp boundary meeting the border fans out into rays | `diag` (white over blue, the boundary rises 1 px per 2 px inward and meets both side edges at row 540) with default settings and `edgeBlend=100`, at 2, 4, 6, 9, 12 and 16 px outside the picture on both sides: over rows 420..659, the largest one-row luma change divided by the steepest slope of a gaussian step of the same height with `sigma = max(4, k)`, the blur the shader intends along the border (limit `T_RAY_JUMP` = 2). Sparse sharp taps make a staircase: 2.5-5.9 before the fix, <= 1.4 after. Skipped in `--self-test` |

The input pictures are generated by `inputs.py`, and each run regenerates them. You can also write
them out on their own: `python tests\quality\inputs.py OUTDIR [name ...] [--size WxH]`. `png.py` is
the PNG reader and writer, written with the standard library only.

## Adjusting thresholds

All limits are constants at the top of `check_quality.py` (`T_RISE`, `T_KINK_ABS`, `T_KINK_REL`,
`T_SHELF`, `T_SEAM`, `T_SYM`, `T_WIDTH`, `T_DETAIL_RMS`, `T_NEGFADE_SEAM`). Each one has a comment
naming the defect it guards. They were chosen so that the build reviewed on 2026-10-17 fails clearly:

| Metric | Limit | That build |
|---|---|---|
| rise after fall | 2 | up to 19.6 |
| kink | 2 to 5.7 | up to 22.1 |
| shelf | 1.5 | up to 9.3 |
| seam step | 4 | up to 18.6 |
| symmetry | 3 | 93 |
| width dependence | 3 | 30 |
| 16 px bands, seam RMS | 12 | 32 to 56 |
| 64 px bands, seam RMS | 2 | 4.0 to 22.4 |
| negative fade start, seam step | 4 | 78 |

The ideal outputs from `--self-test` pass with margin. If you change a limit, run `--self-test` and
check that the ideal still passes. The ideal is built as follows: the far field is the renderer's own
`edgeBlend=0` output, and within `T` it is blended toward the picture's edge column (blurred 1.5 px
along y) with weight `1 - smoothstep(k / T)`. For the symmetry check the left glow is mirrored to the
right, and the 3700 px output is the 3840 px one shifted. If a deliberate design change moves a
measurement (for example a wider transition), adjust the case list or the limit in the same change and
record why in the comment next to the constant.
